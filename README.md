## 問題の形式

| 形式 | 例 | スマホの操作 | 採点 |
|---|---|---|---|
| 選択 | 1位を当てる／どっちがAさんの絵？（画像） | 番号をタップ | 正解で1点 |
| 並び替え | 年齢が高い順 | ドラッグで上下に並べる | 合っている数÷項目数 |
| 写真マッチング | 子どもの頃の写真は誰？ | 人物から写真へ線を引く | 同上 |
| 言葉マッチング | それぞれの好きな食べ物は？ | 左の言葉から右の言葉へ線を引く | 同上 |
| グループ分け | パクチー食べられる／食べられない | カードを箱へドラッグ | 同上 |

## 問題ごとの追加設定（すべて任意）

| 設定 | 内容 | 設定しない場合 |
|---|---|---|
| 並べる基準（並び替えのみ） | 一番上・一番下の意味（例：北 → 南）をスクリーンとスマホに表示 | 「一番上が①」とだけ表示 |
| 配点倍率 | ×0.5〜×10。問題一覧のプルダウンからも変更できる。部分点にも倍率がかかる | ×1（1問1点） |
| ヒント | 最大5つ。進行画面の「ヒント」ボタン（Tキー）で1つずつ表示。スマホにも出る。出題中は画面右上に「💡 ヒントあります！ あと◯つ」の吹き出しが出て、参加者はスマホの「🙋 ヒントほしい！」で求められる（人数が吹き出しに表示） | 吹き出し・ボタンとも出ない |
| 回答ごとの説明 | 選択肢・項目ごとの一言。正解発表で表示 | 今まで通りの表示 |
| 全体の説明 | 正解発表の下に表示 | 今まで通りの表示 |

ヒントと説明は、表示するまで参加者のスマホには送られません。

## 同率・同じ答え・複数正解

| 形式 | 設定方法 | 採点 |
|---|---|---|
| 並び替え（同率） | 各項目の左の順位（①②…）で、同じ順位を選ぶ（例：千葉①、神奈川3人をすべて②） | 例：千葉1人＋神奈川3人 → 千葉が①、神奈川3人は②〜④のどの順でも正解 |
| 言葉マッチング（同じ答え） | 右側に同じ言葉（例：B型が2人）を入力すると、自動で1枚にまとめる | 複数の人から同じ言葉へ線を引ける。どちらも正解 |
| 選択（複数正解） | 正解のチェックを複数つける | チェックしたどれを選んでも正解 |

- アンケートからの自動作成も対応しています（同じ都道府県・同じ数値は同率、同じ答えは1枚にまとめる、同じ答えの人が複数いれば全員を正解）。
- 正解発表では、同率の項目は「②〜④（同率）」と表示されます。

## アンケートから問題を作る

1. 問題作成画面の「**アンケート**」タブで、**回答者**（クイズの題材になる人）の名前を登録
   - 当日クイズに参加する人の名簿とは**別のリスト**です。空のままなら回答者が名前を入力します
2. ひな形（出身地・好きな食べ物・子どもの頃の写真・パクチー・生まれた年など）から質問を追加
3. 「受付中」に切り替え、表示された**回答用URL／QR**を回答者に共有
4. 回答者はリストから名前を選んで回答（あとから修正も可）。回答と未回答者は管理画面で確認
5. 質問ごとの「**この回答から問題を作る**」→ 形式と使う人（2〜8人、ランダム選択も可）を選んで「下書きを作る」
6. 「問題を編集」タブに下書きが入るので、確認・修正して「保存」

| 質問の種類 | 作れる問題 |
|---|---|
| 都道府県 | 並び替え（北→南の基準つき）／言葉マッチング |
| 数値 | 並び替え（大きい順・小さい順） |
| 自由記述 | 言葉マッチング／「この回答は誰？」の選択 |
| 選択式 | グループ分け |
| 写真 | 写真マッチング |

### 顔写真と、人を知ってもらう問題

- アンケートの最初に「**顔写真をアップロードしてください**」を入れられます（「アンケート」タブの「顔写真」でオン／オフ、必須にするかも選べる）
- どの質問も「必須」にできます。写真の質問も追加できます（画像のみ。PDFなどは映せないため対象外）

| 元にする回答 | 作れる問題 |
|---|---|
| 顔写真 | この人は誰？（顔を見せて名前を選ぶ）／○○さんはどの人？（顔写真から選ぶ）／名前 ↔ 顔写真の写真マッチング |
| 出身地・自由記述・選択式・数値 | ○○さんの◯◯は？（主役の顔写真つき・ほかの人の回答が選択肢） |
| 上記以外の問題 | 「顔写真を添える」にチェックすると、名前と一緒に顔写真を表示 |

問題作成画面では、どの問題にも「**問題の画像**」を1枚付けられます（スクリーンの左側とスマホに表示）。

- 本人の回答は「回答ごとの説明」に自動で入ります（正解発表で表示）。
- 同じ回答の人が含まれる場合は、同率・同じ答えとして自動で扱います（お知らせが出ます）。
- アンケートは開催ごとに別々です。回答URLには開催のIDが含まれます。

## 「開催」のしくみ

飲み会ごとに「開催」を作り、それぞれに次のものを保存します。

| 開催ごとに持つもの | 内容 |
|---|---|
| タイトル | 例：「10月の飲み会クイズ」。スクリーンとスマホに表示 |
| パスワード | 問題作成画面・進行画面でその開催を開くときに必要 |
| 問題 | 開催ごとに別々に保存（ほかの開催から複製も可） |
| 参加者名簿 | ほかの開催から引き継ぐ／名前を手で追加・削除 |
| BGM（任意） | 音源ファイルを登録できる（未登録なら自動作成の音楽） |
| 回答・得点 | その開催の分だけ。「リセット」で消せる |

- **新しい開催を作るとき**は `config.js` の **管理者PIN（ADMIN_PIN）** が必要です。
- 開催のパスワードを忘れたときも、管理者PINで開けます。
- 以前の版で作った問題は、最初に開いたときに「**これまでの問題**」という開催へ自動で移ります（パスワードは管理者PIN）。

### 参加者名簿

- 名簿があると、参加者はスマホで**自分の名前をタップするだけ**で参加できます（名簿にない人は名前を入力）。
- 新しい開催を作るときに「参加者名簿：◯◯から引き継ぐ」を選ぶか、開催の設定で「◯◯から引き継ぐ」を押すと、その開催の名簿と実際に参加した人の名前をまとめて取り込みます。
- 名前はまとめて追加できます（改行・読点「、」・カンマ区切り）。

### 問題が事前に見えないしくみ

参加者のスマホには、進行画面で**出題した問題だけ**が届きます（正解は届きません）。
ただし、データベースは誰でも読める簡易設定のため、詳しい人が直接のぞけば中身を見ることはできます。社内の飲み会用と割り切って使ってください。

## 音（BGM・効果音）

音は**プロジェクターにつないだPC（host.html）だけ**で鳴ります。

| 場面 | 音 |
|---|---|
| 受付中・順位表示 | にぎやかなBGM（登録した音源があればそれ） |
| 回答中 | 考え中BGM、残り5秒からカウント音 |
| 予告 | 短いドラムロール |
| 出題 | 「ジャジャン」 |
| 締切 | ベル（メニューで笛・ジャン！に変更可） |
| 正解発表 | ドラムロール →「ピンポーン」 |
| 選んだ人の結果 | 短いドラムロール |
| 最終結果 | ファンファーレ |
| 参加者が来たとき | 「ポン」 |

- 画面下の「**BGM**」「**効果音**」ボタンでオン／オフ（Mキーで BGM 切り替え）。設定はPCに記憶されます。
- ブラウザの決まりで、**ページを開いたあと一度クリックするまで音は出ません**。
- 合成音なので著作権の心配はありません。音源ファイルを登録する場合は、使用が許可されたものを選んでください。

## 本番の準備

### 手順1　Firebase（済んでいれば不要）

1. https://console.firebase.google.com/ でプロジェクト作成 → 「Realtime Database」を作成
2. 「ルール」タブに `database.rules.json` の中身を貼り付けて「公開」
3. 「プロジェクトの設定」→「全般」→「マイアプリ」の `</>` でアプリ登録 → 表示された値を `config.js` に貼り付け
4. `config.js` の `ADMIN_PIN` を自分だけが知る番号に変更

### 手順2　GitHub に置く

1. リポジトリで「Add file」→「Upload files」
2. 12ファイルをまとめてドラッグ＆ドロップ（既存は上書き）→「Commit changes」
3. 1〜3分後に反映（初回は「Settings」→「Pages」で Branch を `main` / `(root)` にして Save）

### 手順3　開催を作って問題を作る（admin.html）

1. 「＋ 新しい開催を作る」→ タイトル・パスワード・（任意）名簿の引き継ぎ・問題の複製・管理者PIN →「作成して開く」
2. 左上の「設定」で名簿・BGM・タイトル・パスワードを変更
3. 右側で問題を作成（形式・問題文・制限時間・選択肢や項目・正解）→「保存」
4. 問題ファイル（JSON）がある場合は、問題一覧の「📥 ファイルから取り込む」でまとめて追加（下の「問題ファイルの一括取り込み」参照）

### 手順4　当日（host.html）

1. 開催を選んでパスワードを入力 → **その開催が参加者向けの「本番」になります**
2. 画面を一度クリックして音を有効にし、F11で全画面、Hキーで操作バーを隠す
3. Space（または →）で進行：**予告 → 出題 → 締切 → 正解発表 → 次の問題の予告**（最後の問題のあとは最終結果）
   - 途中経過は自動では出しません。見せたいときに黄色の「🏆 順位（途中経過）」ボタンを押してください（そのあと Space で次の問題へ）
   - 予告：問題文の前に「Q1／◯点（満点）／ヒントあります！（ヒントがある問題のみ）」を表示。スマホにも同じ内容が出ます
   - 出題中も、画面上部に配点（◯点）を常に表示します

| キー・ボタン | 動き |
|---|---|
| Space / → | 次へ |
| T（またはヒントボタン） | ヒントを1つ表示 |
| H | 操作バーを隠す／出す |
| M | BGM のオン／オフ |
| 参加者を選ぶ＋「この人の結果」 | 選んだ1人の各問の回答・○△×・得点・順位を表示 |
| 開催を切り替え | ほかの開催を選び直す（参加者のスマホも自動で切り替わる） |
| リセット | この開催の参加者・回答・得点を消去（問題と名簿は残る） |

## 注意点

- データは誰でも読み書きできる簡易設定です。URLを社外に広めないでください。
- パスワードは変換（ハッシュ化）して保存していますが、本格的な認証ではありません。
- BGMの音源ファイルは4MBまで。無料プラン（保存1GB・転送10GB/月）で十分まかなえる想定です。
- 参加者のスマホはインターネット接続が必要です（会場Wi-Fiまたはモバイル回線）。

## 問題ファイルの一括取り込み（JSON）

問題作成画面（admin.html）の問題一覧にある「📥 ファイルから取り込む」で、JSON ファイルの問題をまとめて追加できます。

- 新しい開催として使うときは、先に「＋ 新しい開催を作る」で空の開催を作り（問題は「空の状態から作る」）、開いてから取り込みます。
- 今ある問題の**後ろに追加**します（上書きはしません）。
- 1問でも不備があると、どの問題のどこが悪いかを表示して**全体を中止**します（途中まで取り込まれることはありません）。
- 文字だけの問題に対応しています。写真マッチング（`match`）と画像は取り込めないため、取り込んだあとに画面で追加してください。
- 番号（`answer`・`group`・`ranks`）は **1から数えます**。

### ファイルの形

```json
{
  "title": "メモ用のタイトル（開催のタイトルには使われません）",
  "questions": [ 問題, 問題, … ]
}
```

### すべての形式で使える項目（すべて任意）

| 項目 | 内容 | 省略したとき |
|---|---|---|
| `timeLimit` | 制限時間（秒）。0 で制限なし | 30 |
| `points` | 配点倍率（0.5・1・1.5・2・3・5・10 のどれか） | 1 |
| `hints` | ヒントの配列（5つまで） | なし |
| `explain` | 全体の説明（正解発表で表示） | なし |
| `shuffle` | 並び替え・グループ分けの表示順をシャッフルするか | true |

### 形式ごとの書き方

| 形式 | 必須の項目 | 例 |
|---|---|---|
| 選択 | `"type": "choice"`、`options`（選択肢の配列）、`answer`（正解の番号。複数正解は配列） | `"options": ["A", "B", "C"], "answer": 2` |
| 並び替え | `"type": "order"`、`items`（**正しい順**に並べる）。任意で `topLabel`・`bottomLabel`、同率は `ranks` | `"items": ["千葉", "神奈川", "東京"], "ranks": [1, 2, 2]` |
| 言葉マッチング | `"type": "pair"`、`pairs`（`[左, 右, 説明]` の配列。説明は省略可） | `"pairs": [["Aさん", "B型"], ["Bさん", "B型"]]` |
| グループ分け | `"type": "group"`、`groups`（箱の名前）、`items`（`text` と `group`（箱の番号）） | `"items": [{ "text": "イルカ", "group": 1 }]` |

- 選択肢・項目は文字だけなら `"文字"`、説明（正解発表で表示）をつけるなら `{ "text": "文字", "note": "説明" }` と書きます。
- 言葉マッチングで同じ言葉（例：B型が2人）を書くと、自動で1枚にまとまります。

## アンケート画像のGoogleドライブ・バックアップ（任意）

画像はこれまでどおりアプリ（Firebase）に保存したまま、**アンケートで集めた画像の控え**をドライブのフォルダにも保存できます。保存したファイルに共有設定はしません。

### 初回の準備（約10分）

1. Googleドライブに保存先フォルダを作る（例：「EGクイズ写真バックアップ」）。フォルダURLの `folders/` のあとの文字列（フォルダID）を控える
2. https://script.google.com/ で「新しいプロジェクト」→ `gas/drive-backup.gs` の中身を貼り付けて保存
3. 歯車「プロジェクトの設定」→「スクリプト プロパティ」に2つ追加
   - `FOLDER_ID`：手順1のフォルダID
   - `TOKEN`：自分で決めた合言葉（英数字で長めに）
4. エディタで関数 `authorize` を選んで「実行」→ ドライブへのアクセスを許可
5. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**／アクセスできるユーザー：**全員**
   - 「デプロイ」→ 表示された**ウェブアプリのURL**を控える
6. 問題作成画面「アンケート」タブの一番下「ドライブにバックアップ」にURLと合言葉を入力 →「接続テスト」

### 使い方

- 「未バックアップの画像をドライブに保存」で、まだ控えていない画像だけを保存します（二重保存はしません）
- 「この画面を開いている間は自動でバックアップ」をオンにすると、新しい回答の画像を自動で保存します
- ドライブには「開催名」のフォルダができ、`名前_質問_画像ID.jpg` の名前で保存されます
- URLと合言葉は**そのPCのブラウザにだけ**保存されます（データベースには入りません）

### 注意

- 「アクセスできるユーザー：全員」は、URLと合言葉を知っている人だけが保存できる、という意味です。ドライブのファイル自体は公開されません
- GASのコードを修正したときは「デプロイを管理」→ 編集 →「新しいバージョン」で更新してください（URLは変わりません）
- アプリ側で回答や開催を削除しても、ドライブの控えは自動では消えません
